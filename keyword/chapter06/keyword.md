- `gcTime`은 무엇인가요? 🍠
    
    `gc`는 Garbage Collection의 약자
    데이터가 사용되지 않을 때 메모리에 얼마나 머무를지를 결정
    
    - 컴포넌트가 화면에서 사라지면(관찰자가 0명이 되면), 해당 쿼리는 `inactive` 상태가 됨.
    - 이 `inactive` 상태가 된 시점부터 `gcTime` 타이머가 돌아가고, 시간이 다 되면 메모리에서 삭.
    - **기본값:** 5분 (`5 * 60 * 1000`).
- `staleTime`은 무엇인가요? 🍠
    
    `stale`은 신선하지 않은 이라는 뜻 즉, 데이터를 서버로부터 받아온 후 얼마나 오랫동안 유효한 상태로 유지할 것인가를 결정하는 시간
    
    - **Fresh 상태:** 설정한 `staleTime`이 지나지 않은 상태입니다. 이때는 컴포넌트가 다시 마운트되어도 서버에 다시 요청하지 않고 캐시된 데이터를 즉시 사용.
    - **Stale 상태:** `staleTime`이 지난 상태. 데이터가 유효하지 않다고 판단하며, 특정 조건(창 포커스, 마운트 등)이 충족되면 백그라운드에서 데이터를 다시 가져옴.
    - **기본값:** `0` 데이터를 받자마자 유효하지 않은것으로 간주, 기회만 생기면 다시 가져옴
- 두 값을 어떤 식으로 설정하여야 `캐싱 전략에 유리`한가요? 🍠
    
    **`staleTime` < `gcTime`** 를 유지해야함 . 데이터가 신선하지 않더라도(stale), 메모리에는 남아 있어야(gcTime) 사용자에게 '지난 데이터'라도 먼저 보여주며 백그라운드에서 업데이트하는 UX를 제공할 수 있기 때문

1. 페이지네이션의 구조적 차이점
     1. 오프셋 기반: 전체 데이터 중 특정 구간을 산술적으로 지정하는 방식임.
        동작 원리: 사용자가 요청한 page 번호와 size를 곱하여 건너뛸 개수를 계산함.

        데이터 적재: 화면에는 항상 현재 페이지의 데이터만 렌더링됨.

    2. 커서 기반: 마지막으로 확인한 지점을 기준으로 다음 구간을 탐색하는 방식

        화면에는 데이터가 누적되어 길게 이어지는 형태를 보임
